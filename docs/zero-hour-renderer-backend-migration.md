# Renderer backend decision and migration — 2026-09-21

Status: **accepted technical decision under `docs/zero-hour-linux-port-plan.md` §9**. Change ID: `RENDERER-BGFX-2026-09-21`. This is an implementation-ready change plan, not a claim of completed rendering. It supersedes the provisional SDL_GPU *device/backend* selection only; SDL3 remains the window, event and input layer. Original retail content is read-only and is not part of this artifact.

## Decisive gap and reproduced coverage

`WW3D::Render(SceneClass*,CameraClass*,...)` applies the camera viewport then calls `DX8Wrapper::Clear` while the original frame is active, before that scene's draw and before later scenes or presentation. D3D8 `Clear(0,NULL,...)` scopes to that viewport. See `delivery/evidence/cnc-generals-zero-hour/milestone_22_backend_gap_06c3c.md` for exact source paths, SDL_GPU public-API limit and original semantics. SDL_GPU 3.4.14 exposes full-attachment pass-start CLEAR and draw viewport/scissor, but no public active-pass rectangle color/depth/stencil clear; the existing `SdlGpuDevice` cannot represent it without changing behavior.

The reproducible public-bgfx probe is `tools/renderer/bgfx_viewport_clear_probe.cpp`. It creates a 160×120 BGRA8+D24S8 framebuffer, uses ordered views in one bgfx frame to clear the entire target red/depth .25/stencil 7 and then only x40–119/y30–89 blue/depth 1/stencil 0, and reads back color. Later full-target draws test depth LESS at .5 and stencil EQUAL 0 independently: only the inset turns green, proving outer depth and stencil preservation. It passed exit 0 on the host's RTX 4070 with Vulkan 1.4.341, NVIDIA 610.57.04, bgfx `81d81fba72c42d348c589514c774bbfe01e110fa`. The probe uses public `setViewRect`, `setViewClear`, `touch`, `submit`, `blit` and `read` APIs; bgfx's Vulkan implementation routes depth/stencil aspects and `VkClearRect` through its public view-clear path. This is evidence for the exact §9 abstraction gap, not for all original scene categories.

Reproduce without changing the repository: obtain matching public bgfx/bx/bimg sibling source trees in a temporary directory, build `bgfx-shared-lib` using the upstream Linux GCC release64 project, compile the probe against those headers/library with C++20, then pass upstream `examples/runtime/shaders/spirv/vs_cubes.bin` and `fs_cubes.bin` as its two arguments. The test requires a host-accessible Vulkan driver; restricted sandboxes may hide the NVIDIA ICD. Do not copy retail assets into the probe or repository.

## Migration invariants and work items

- `RB-01` Contract: keep public engine-facing headers backend-neutral and preserve opaque handle identity. Add a recorder-visible *ordered viewport clear* operation with independent color, depth and stencil flags/values, target generation, clipped rectangle and exact command-order semantics. Validate illegal timing, dimensions, formats, target lifetime, state exhaustion and uninitialized load before GPU submission. Preserve existing full-target pass clear/load behavior.
- `RB-02` Backend: replace only `SdlGpuDevice` ownership/submission with a bgfx implementation behind `GpuDevice`; retain SDL3 platform/input, original W3D/WWShade/GameClient producers, source authority, and the no-private-Vulkan rule. Map textures, buffers, indexed base-vertex draws, render targets, shader/pipeline states, scene/view order, resize/present, device failure and cleanup using public bgfx. Bound view IDs and report exhaustion, never silently reorder or drop draws. No silent proxy draw for a clear.
- `RB-03` Shader/format closure: recheck every M2 `legacy-api-mapping.tsv` entry against the selected public backend and existing CPU fallback/rejection; package the repository-owned GLSL/SPIR-V shader families into bgfx-compatible binaries with an offline, reproducible toolchain. Retain semantic shader/state coverage, point size, premultiplied alpha, BC fallbacks, four-uniform-block contract or an explicitly validated equivalent. Unknown required source categories remain failures.
- `RB-04` Revalidation: rerun M7 recorder contract and M8–M10 UI/world/effects command and shader tests against changed descriptors; rerun M14 real RTX/Vulkan validation, pixel, resource, resize/loss and lifecycle acceptance through bgfx. Then resume M22 06C3C and remaining original retail W3D scene acceptance. M24 05C/05D/06 remains dependent on completed M22 draw provider; M23 and later milestones retain their current dependencies. Previously accepted non-backend code and milestone histories are preserved, not reset.

## Acceptance and boundaries

The migration gate passes only when the committed contract/backend/shader mapping builds in all required configurations, positive and negative recorder tests pass, the checked probe and source-faithful original camera-clear order pass on Vulkan hardware, validation has no relevant errors, and M7–M10/M14 affected acceptance is rerun with explicit evidence grades. The legacy SDL_GPU-specific tests may remain as history or be replaced by equivalent bgfx tests; they cannot count as new backend acceptance. Original retail scene pixels remain M22 acceptance and may not be substituted by the synthetic probe. A source dependency ledger must show which work was preserved and which backend-specific acceptance was rerun.

The migration does not add ARM64, a second GPU requirement, raw Vulkan ownership, new game behavior, retail redistribution, or a gameplay rewrite. bgfx is a new build dependency; pin/reproduce its revision, verify license and offline shader compiler availability, and keep generated or vendored artifacts within repository policy before implementation. If a different required original behavior is later proven to exceed bgfx's public API, reopen §9 with another named reproducer; this decision does not pre-authorize raw Vulkan.
