The caller owns color/depth targets and the source frame. `Begin_Render` starts an active device pass; source `Render(scene, camera)` updates camera, selects its viewport, emits the ordered clear if requested, publishes source state, invokes the original scene render, then flushes original queues. `End_Render` presents only after those operations succeed. A second source render may use a different viewport in the same frame. No file/network authorization applies; caller-owned render targets and read-only retail roots remain the ownership boundary. Reject null scene/camera, inactive frame, unsupported fill/clear/depth state, missing/stale target, and device clear/draw failure before claiming a complete frame. Exception paths reset original `IsRendering`, source state, queues/refcounts and active pass so retry/re-entry is bounded. Do not count a partially recorded frame as acceptance.
