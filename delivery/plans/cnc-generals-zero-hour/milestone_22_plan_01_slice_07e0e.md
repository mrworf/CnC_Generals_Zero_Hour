# M22 plan 01 slice 07E0E: production-order original display bootstrap

## Outcome and boundary

Requires accepted 07E0D and prerequisites 07E0D1–D3. In the full-presentation Linux executable only, an explicit empty-scene graphics profile acquires a public bgfx GPU device and `OriginalGpuEdge` before `GameMain` enters `GameEngine::init`. The edge outlives original GameClient display/UI/terrain teardown. `LinuxGameClient` selects the canonical original `W3DDisplay`, `W3DView` and `W3DTerrainVisual` factories only when that ready edge and the explicit profile are both present. Default headless factory selection and production data/scenario behavior stay unchanged; no automatic promotion of map-loaded gameplay or shell rendering. Factory-attached rigid pixels are a separate 07E0F child; this slice claims only the empty source frame.

## State, failure and ownership

The profile is all-or-nothing. An unavailable Vulkan device, missing shader set, invalid profile conditions or inactive edge fails before original factory publication. A source initialization failure unwinds original GameClient owner slots before the edge/device is destroyed. The original display owns its 2D/3D scenes and WW3D assets, UI owns the original tactical view, and terrain visual owns the no-map terrain/effect graph in native order. `GameMain` leaves two non-owning aliases (`TheGameClient`, `TheTacticalView`) stale after destruction even in the default fixture; the opt-in GPU process boundary retires those aliases only after `GameMain` returns and verifies all original owner slots are empty. A profile child must not fall back silently to headless after publishing any original owner. Four allocations retained by bgfx/device startup after teardown are process-scoped and measured with an equivalent device-only control. The M20 default no-device absolute allocation assertion remains unchanged; only the opt-in GPU profiles use paired source-owner and device-only residual validation. No retail symlink content is written.

## Tests and acceptance

Add a source/physical startup probe through the real `GameMain` and `GameClient::init`, not a temporary pointer substitution. Positive controls assert original factory/provider identity and owner order, a guarded black empty frame/readback, zero source-owned allocations after teardown, and a second fresh generation. A same-fixture device-only process must have the same post-device residual as the original-factory process; the test must not hardcode or silently absorb that residual into the default M20 baseline. Negative controls reject forced device unavailability before publication and a forced source-owner initialization failure after partial publication with complete rollback; headless/default startup remains unchanged. Run five rebuilt non-GPU suites, leak-capable GCC/Clang sanitized controls, GCC Debug/Clang Release repeated host Vulkan, provider and ledger checks. Commit only after all pass. Rigid factory pixels, map-loaded terrain, shroud, tracks, shadows, UI overlays, movies and general production factory promotion remain separate pending slices.

## Result and commit boundary

The explicit profile constructs the public bgfx device, edge and owned 800x600 targets before `GameMain`; real original GameClient init selects one canonical display, tactical view and empty terrain visual. The bounded update reaches `W3DDisplay::draw`, and readback proves the black empty source frame. After `GameMain`, owner slots and subsystem list are checked empty before retiring the original non-owning GameClient/tactical aliases. Paired fresh processes show both original and device-only profiles retain exactly four process-scoped allocations after device teardown (26 versus the established baseline 22), while their GameMain allocation delta is identical. The default M20 absolute-baseline path remains unchanged. Forced device, conflicting-mode and partial terrain-factory failures roll back without published owners. The exact tree passes five full suites and repeated physical validation. Evidence: [07E0E](../../evidence/cnc-generals-zero-hour/milestone_22_slice_07e0e.md). This commit excludes 07E0F rigid pixels and the unrelated renderer diagnostic.
