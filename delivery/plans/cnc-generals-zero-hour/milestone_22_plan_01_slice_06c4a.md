# M22 plan 01 slice 06C4A: read-only retail W3D chunk-family gate

## Outcome and boundary

Requires accepted 06C3. Before enabling the authored WWShade branch or changing source rendering, establish a conservative yes/no/unknown gate for whether the available retail W3D archive contains the SHDMESH top-level chunk family. Add a bounded, read-only BIG/W3D aggregate checker that prints only counts by public numeric chunk family, never private logical names, paths, bytes or hashes. Use the already supplied ignored retail symlink as input only; it must never be opened for writing, copied, chmod'ed, or modified. This slice does not claim a complete retail scene, WWShade runtime support, or M22 acceptance. Any opaque payload makes a zero-SHDMESH result `unknown` until C4B classifies it; it must never silently become `no`.

## Entry, errors and verification

The checker takes explicitly selected caller-owned archive paths, validates BIG header/table/entry extents, scans only `.w3d` entries, validates top-level W3D chunk bounds including the subchunk-size flag, and reports archive count, W3D entry count, numeric mesh/HLOD/SHDMESH/other top-level counts. Malformed headers, table ranges, names, or entry offsets fail closed without emitting private identifiers. Malformed chunk spans fail by default; an explicit report-only mode excludes and counts each opaque entry, returning `unknown` rather than `no` if no valid SHDMESH is seen. A synthetic owned BIG/W3D positive test proves exact family counts and enabled-family signal; negative tests cover truncation, invalid ranges and malformed chunk lengths, including report-only classification. Run the checker read-only against the available Zero Hour archive, record only derived aggregate counts, and state any base-archive or opaque-entry coverage gap explicitly. Run GCC/Clang asset-free full suites and sanitizer test; one commit with plan, test, checker and evidence. C4B owns opaque classification, enabled compile/runtime branch and complete mixed frame.
