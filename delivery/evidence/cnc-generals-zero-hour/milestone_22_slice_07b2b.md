# M22 07B2B deterministic W3D dependency identity evidence

The original `check_m20_w3d_identity.py` searched all raw `ldd` output for `d3d`. A Clang Debug full-suite run therefore reported a false Direct3D dependency when an ASLR hexadecimal mapping address contained that substring; immediately repeating `ldd` for the same executable listed only normal Linux DSOs. The checker now examines the dependency name (left of `=>`, or the executable path on loader lines), never the mapping address. It still rejects names containing `d3d` or `direct3d`.

Unit controls pass for ASLR address-only `d3d` (negative) and `libd3d8.so`, `libvkd3d.so`, and `libDirect3D.so` sonames (positive). The real `original_w3d_schema_identity` passes in all four existing GCC/Clang Debug/ASan+UBSan presets and in 30/30 fresh Clang Debug invocations. GCC/Clang Debug and GCC ASan+UBSan full asset-free suites pass 189/189; Clang ASan+UBSan passes 188/188 with only the separately pending 07B2 source-scene test excluded. That test's executable still predates the final 07B2 shader edit and will be rebuilt for 07B2 acceptance. All ledger checks are clean. This checker-only prerequisite makes no status-pixel or production-display claim; 07B2 remains separate.
